## Поставленные задачи (исходные формулировки)

### Сессия 1: Файлы (загрузка, хранение, скачивание)
Цель: Реализовать базовую работу с файлами.
Хранилище: S3/MinIO (файлы вне БД, в БД лишь путь) — **пересмотрено в ходе сессии** на локальный диск.
Метаданные в PostgreSQL: путь, имя, тип, размер, владелец, связь с сущностью.
API: загрузка/скачивание через защищённые endpoint-ы.

### Сессия 2: Архитектура модулей
Цель: Заложить структуру для файлов, отчётов и постов.
Модуль files: сервис хранилища + сервис метаданных + endpoint-ы.
Модуль pdf-export: асинхронная генерация PDF (ID заявки → PDF) на сервере.
Модуль posts: Markdown/WYSIWYG + прикрепление файлов (функционал модуля files).

### Сессия 3: Frontend. Design system + Component Library
Создание собственной библиотеки часто используемых компонентов для единообразия интерфейса.

### Сессия 4: Функционал администратора
- Добавление новых пользователей, назначение ролей, сброс пароля.
- Редактирование всех записей на всех этапах: пользователи, эксперты, заявки, стена новостей, направления, конкурсы, критерии оценивания.

### Сессия 5: Функционал целевой аудитории
- Создание заявки, отправка заявки на проверку.

### Сессия 6: Функционал экспертов и проведения экспертиз
- Проверка заявок, выставление рецензии.

### Промежуточная сессия: Рефакторинг и проверка кода

## Заметки по выполненным сессиям

### Сессия 1 «Файлы» — выполнена (v1.0.3)

- Хранилище: локальный диск `./uploads/` (env `UPLOAD_DIR`), папка заявки `<owner>-<app>-<время>`, согласия в `consents/`. В БД — относительные пути `uploads/...`.
- Схему не меняли: материалы → `additional_materials`, согласия → `consent_files` (согласие синхронизируется в legacy `team_members.consent_file_path`).
- Auth: email+пароль (argon2id через `Bun.password`), JWT HS256 (`jose`) в httpOnly-cookie `arbuz_session`; Bearer тоже принимается. Секрет `JWT_SECRET` (в prod обязателен).
- Разрешены PDF/DOCX/JPEG/PNG/MP4 (magic bytes + ext), UUID-имена, лимиты 10МБ/файл и 25МБ/заявку. Права: владелец/админ.
- Эндпоинты: `/api/auth/*`; `/api/applications/:id/files*`; `/api/applications/:id/team-members/:memberId/consents*`.
- Скрипты: `bun seed` (`SEED_DEMO=true` — демо-заявитель/заявка/участник; демо `demo@arbuz.local`/`demo12345`), `bun storage:cleanup` (cron).
- Аудит: `logs/audit.log`. ClamAV сознательно не внедряли — зафиксировано в README «Заметки для деплоя».

### Сессия 2 «Архитектура модулей» — выполнена (v1.1.0)

- Схема расширена миграцией `20260908154317_session2_modules`: `pdf_export_jobs` + `posts_files`.
- pdf-export: асинхронный воркер `scripts/pdf-worker.ts`, pdfmake (Roboto/кириллица), 9 секций + бюджет (шаблон → техдолг).
- posts: CRUD админа (Markdown), чтение опубликованного для остальных; вложения через `posts_files` + модуль files.
- `app.ts`/`index.ts` разделены; multipart в `lib/multipart.ts`; `file_type` в БД — короткие токены (fix).
