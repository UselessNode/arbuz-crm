# Технический долг и открытые вопросы

Список осознанных «хвостов», которые закроются в следующих сессиях. Здесь живут
моменты, отложенные не из-за лени, а из-за зависимостей от будущего кода/решений.

Аудит кода проведён 2026-09-11; приоритетные проблемы исправлены в **1.9.0**
(см. `CHANGELOG.md`). Ниже — что осталось. Формат: `файл:строка` — суть.

## ✅ Исправлено в 1.9.0

- Хранилище файлов: единая конвенция путей (БД `uploads/…` ↔ физический `UPLOAD_DIR`),
  устранена двойная вложенность; `storage:cleanup` больше не удаляет «живые» файлы.
- Отправка/создание заявки: системные статусы — в `lib/app-status.ts` (без хардкода
  имени/id); валидация `tender_id`/`direction_id`/`status_id`.
- PDF-воркер: watchdog и обработка аварийного завершения.
- Доступ к файлам заявки: чтение/скачивание доступно назначенному эксперту.
- Frontend: удалён недостоверный `APPLICATION_STATUS_OPTIONS`; статусы — с бэкенда;
  устранены проглоченные ошибки (форма заявки, предпросмотр Markdown), stale-closure
  в списке пользователей, вложенный `<a><button>`, a11y таблицы/модалки, inline-стили,
  спиннер загрузки, `AccountPage` без пустого экрана.

## Backend (осталось)

- **Роуты содержат бизнес-логику.** `files.routes.ts` — расчёт квоты и сериализация;
  вынести в `*.service.ts` (заголовки скачивания уже вынесены в `modules/files/download.ts`).
- **Дублирование утилит.** `lib/parse.ts` (1.17.0) содержит `parseId`/`requiredText`/
  `optionalText`/`optionalBool`/`oneOf`; его использует модуль `reviews`. Остальные модули
  (`tenders`, `directions`, `statuses`, `files.routes`, `posts.attachments`) ещё держат
  локальные копии — перевести на `lib/parse.ts`.
- **Логирование.** `lib/logger.ts` пишет в `logs/audit.log` синхронно (`appendFileSync`);
  нет ротации (для слабого сервера приемлемо, но при росте нагрузки — пересмотреть).
- **Аутентификация.** `auth.routes.ts` — проверка пароля только для существующих
  пользователей (тайминг-энумерация email). Fallback: единый ответ об ошибке уже есть.
- **Пользователи.** `users.routes.ts` — inline-массив ролей дублирует `ROLE_VALUES`;
  `PASSWORD_MIN_LENGTH` (`users.service.ts`) дублирует `auth/credentials.ts`; `_actorId`
  не используется в `createUser`/`resetPassword`.
- **Критерии оценки.** ✅ Закрыто в 1.14.0: проверка `min_value <= max_value` и `weight > 0`.
  История правок критериев удалена в 1.17.1 (таблица `evaluation_criteria_history`, API и UI).
- **`consent_file_path`.** Пустая строка как плейсхолдер в NOT NULL-колонке
  (`team-members.service.ts`, `files.service.ts`, `seed/applications.ts`). Чисто — сделать колонку
  nullable (правка схемы) либо гарантировать наличие согласия.
- **`PATCH /api/posts/:id` заменяет документ целиком** (клиент присылает `title`/`content`/
  статус целиком). Для одного администратора этого достаточно; при совместном редактировании
  перейти на частичный патч с проверкой `updated_at`.
- **Рецензии.** `reviews.service.ts` — нестрогий тип `rating`; `listReviews` без пагинации.
- **`DocNode = any`.** `pdf-document.ts` — обход типизации pdfmake (единственный `any`).

## Frontend (осталось)

- **Типизация иконок.** `IconName = string`: опечатка компилируется. Сейчас в dev пишется
  `console.warn` об неизвестном имени; строгий union мешает авто-подхвату SVG — оставлено.
- **Тона бейджей.** `tokens.css` содержит и старый набор тонов, и новый расширенный
  (`-light`/`-dark` варианты, 18 тонов); базовые значения в новом блоке переопределяют старые.
  Старый блок — кандидат на удаление после проверки цветов в UI.
- **Форматы данных.** ✅ Закрыто в 1.17.0: общий тип `UserBrief` (`api/types.ts`) используют
  `ReviewListItem.expert`, `ApplicationReview.expert`, `ExpertItem`, `owner`.
- **`Select`** возвращает `onChange(value: string)`, из-за чего в `UsersPage` есть касты
  `value as RoleType`. Типизировать обобщённо.
- **Рантайм-импорт из `@arbuz/shared` во фронтенде запрещён** — только `import type`.
  `packages/shared/index.ts` реэкспортирует сгенерированный Prisma-клиент (CommonJS), поэтому
  импорт значений тянет его в браузерный бандл и dev-сервер падает с `exports is not defined`
  (белая страница). Рантайм-значения зеркалятся локально: `lib/roles.ts`, `lib/post-status.ts`,
  `api/pdf-export.ts`; следит смоук-тест `frontend-shared-imports.smoke.ts`. Правильно решить —
  вынести константы в отдельную точку входа пакета (`@arbuz/shared/constants`) через `exports`.
- **Слои сторонних библиотек против наших оверлеев.** `Modal` использует `z-index: 100`, а
  сторонние попапы бывают ниже (у MDXEditor — до 52) и оказываются за окном. Поэтому редактор
  публикаций живёт на странице; при подключении новых библиотек с порталами внутри модалок
  проверяйте их `z-index`.
- **Ресайз картинок в редакторе отключён.** `imagePlugin({ disableImageResize: true })`: MDXEditor
  хранит размеры атрибутами, которые санитайзер вырезает, — иначе картинка молча теряла бы размер.
  Если понадобится — разрешить `width`/`height` у `img` в `modules/posts/markdown.ts`.
- **Carousel.** `aria-hidden` слайды сохраняют фокусируемые элементы (нужен `inert`).
- **Обёртка API публикаций.** `postsApi.get` используется страницей публикации
  (`/admin/posts/:postId`); `applicationsApi.submit/validation` и `reviewsApi.update` — MVP-2/3.
- **Календарь — только мышь.** `DatePicker` (1.16.0) — кастомный календарь без ввода даты
  с клавиатуры и стрелок для перемещения по дням. Если понадобится a11y-полнота — добавить
  roving tabindex и ввод по маске. Ручной ввод даты намеренно убран (валидация диапазона
  и подсветка важнее скорости ввода для целевой аудитории).
- **Календарь в модалке.** С 1.19.0 `DatePicker` рендерит попап в портале (`document.body`,
  `position: fixed`), чтобы он не обрезался границами модального окна. Из-за этого ловушка
  фокуса диалога (Tab) не видит кнопки календаря и возвращает фокус в окно — при полноценной
  a11y-доработке перенести попап в контейнер диалога либо включить его в ловушку.
- **Поиск в списках.** Для пагинируемых списков (пользователи/заявки/посты) поиск серверный;
  небольшие справочники (рецензии, конкурсы, направления) фильтруются на клиенте — при росте
  данных перевести на `q` в API.
- **Справочники в списках заявок.** `ApplicationsPage` перезапрашивает статусы и конкурсы
  при каждой смене страницы/фильтра — при желании вынести в отдельный `useEffect` с загрузкой
  один раз.
- **Вердикты — справочник в БД.** С 1.17.0 `application_reviews.status_id` ссылается на
  `review_statuses` (enum `ReviewStatus` удалён). При добавлении/удалении вердиктов следите
  за флагом `is_default`: он выставляется новой рецензии (проверка на сервере).

## Сессия 2

- **PDF-выгрузка должна совпасть с интерфейсом заявки.** Состав и порядок 9 секций
  и таблицы бюджета в `modules/pdf-export/pdf-document.ts` синхронизированы с UI в 1.14.0;
  секция 9 «Дополнительные материалы» теперь выводит список файлов заявки.
- **Шрифт PDF**: используется комплектный Roboto из pdfmake (поддерживает кириллицу).
  Если на проде понадобится иной гарнитур (брендовый/государственный) — заменить
  шрифты в `loadFonts()` отдельными TTF-файлами.
- **Markdown-редактор для постов**: ✅ закрыто в 1.11.0 — используется WYSIWYG
  `@mdxeditor/editor`; на выходе Markdown, HTML рендерит/санитизирует сервер (ленивый чанк).
- **Размер файлов вложений постов** не показываем: в таблице `files` нет колонки
  размера (в схеме есть только у `additional_materials`/`consent_files`). Если UI
  потребует размер — добавим позже (правка схемы) либо посчитаем на лету.
- **`files`/`file_categories`**: общий реестр файлов пока используется для вложений
  постов и PDF-выгрузок; «полноценный» модуль с категориями не развиваем до появления
  реальной потребности.

## Отложенные решения

- **Антивирус**: ClamAV не внедряем (слабый сервер; строгий allowlist + проверка
  содержимого + UUID + запрет исполнения). При желании позже — on-demand `clamscan`.
- **Автотесты**: с 1.18.0 есть смоук-тесты backend (`bun test:smoke`, `apps/backend/tests/`);
  коллекция Postman и прогон через Newman — по-прежнему в планах (`docs/api-testing-postman.md`).
- **Очистка старых файлов** — `bun storage:cleanup`, повесить в cron на проде.
- **Пагинация `/api/reviews`** — сейчас список без ограничения; добавить при росте данных.
