# Технический долг и открытые вопросы

Список осознанных «хвостов», которые закроются в следующих сессиях. Здесь живут
моменты, отложенные не из-за лени, а из-за зависимостей от будущего кода/решений.

Аудит кода проведён 2026-09-11; приоритетные проблемы исправлены в **1.9.0**
(см. `CHANGELOG.md`). Ниже — что осталось. Формат: `файл:строка` — суть.

## ✅ Исправлено в 1.9.0

- Хранилище файлов: единая конвенция путей (БД `uploads/…` ↔ физический `UPLOAD_DIR`),
  устранена двойная вложенность; `storage:cleanup` больше не удаляет «живые» файлы.
- Отправка/создание заявки: системные статусы — в `lib/app-status.ts` (без хардкода
  имени/id); валидация `tender_id`/`direction_id`/`status_id`.
- PDF-воркер: watchdog и обработка аварийного завершения.
- Доступ к файлам заявки: чтение/скачивание доступно назначенному эксперту.
- Frontend: удалён недостоверный `APPLICATION_STATUS_OPTIONS`; статусы — с бэкенда;
  устранены проглоченные ошибки (форма заявки, предпросмотр Markdown), stale-closure
  в списке пользователей, вложенный `<a><button>`, a11y таблицы/модалки, inline-стили,
  спиннер загрузки, `AccountPage` без пустого экрана.

## Backend (осталось)

- **Роуты содержат бизнес-логику.** `files.routes.ts` — расчёт квоты и сериализация;
  вынести в `*.service.ts` (заголовки скачивания уже вынесены в `modules/files/download.ts`).
- **Дублирование утилит.** `parseId`/`requiredName`/`optionalText` повторяются в
  `tenders.service.ts`, `directions.service.ts`, `statuses.service.ts`, `files.routes.ts`,
  `posts.attachments.ts`; `parseLimitOffset` — в `users.routes.ts` и `applications.routes.ts`.
  Вынести в `lib/`.
- **Логирование.** `lib/logger.ts` пишет в `logs/audit.log` синхронно (`appendFileSync`);
  нет ротации (для слабого сервера приемлемо, но при росте нагрузки — пересмотреть).
- **Аутентификация.** `auth.routes.ts` — проверка пароля только для существующих
  пользователей (тайминг-энумерация email). Fallback: единый ответ об ошибке уже есть.
- **Пользователи.** `users.routes.ts` — inline-массив ролей дублирует `ROLE_VALUES`;
  `PASSWORD_MIN_LENGTH` (`users.service.ts`) дублирует `auth/credentials.ts`; `_actorId`
  не используется в `createUser`/`resetPassword`.
- **Критерии оценки.** ✅ Закрыто в 1.14.0: добавлена проверка `min_value <= max_value` и `weight > 0`,
  изменения пишутся в `evaluation_criteria_history`.
- **`consent_file_path`.** Пустая строка как плейсхолдер в NOT NULL-колонке
  (`team-members.service.ts`, `files.service.ts`, `seed.ts`). Чисто — сделать колонку
  nullable (правка схемы) либо гарантировать наличие согласия.
- **Рецензии.** `reviews.service.ts` — нестрогий тип `rating`; `listReviews` без пагинации.
- **`DocNode = any`.** `pdf-document.ts` — обход типизации pdfmake (единственный `any`).

## Frontend (осталось)

- **Типизация иконок.** `IconName = string`: опечатка компилируется. Сейчас в dev пишется
  `console.warn` об неизвестном имени; строгий union мешает авто-подхвату SVG — оставлено.
- **Форматы данных.** Фигура эксперта описана в трёх местах (`ReviewListItem.expert`,
  `ApplicationReview.expert`, `ExpertItem`) — вынести общий тип `UserBrief`.
- **`Select`** возвращает `onChange(value: string)`, из-за чего в `UsersPage` есть касты
  `value as RoleType`. Типизировать обобщённо.
- **Carousel.** `aria-hidden` слайды сохраняют фокусируемые элементы (нужен `inert`).
- **Мёртвые обёртки API.** `applicationsApi.submit`, `postsApi.get`, `reviewsApi.update`
  пока не вызываются — оставлены под Session 5/6 (отражают существующие эндпоинты).

## Сессия 2

- **PDF-выгрузка должна совпасть с интерфейсом заявки.** Состав и порядок 9 секций
  и таблицы бюджета в `modules/pdf-export/pdf-document.ts` синхронизированы с UI в 1.14.0;
  секция 9 «Дополнительные материалы» теперь выводит список файлов заявки.
- **Шрифт PDF**: используется комплектный Roboto из pdfmake (поддерживает кириллицу).
  Если на проде понадобится иной гарнитур (брендовый/государственный) — заменить
  шрифты в `loadFonts()` отдельными TTF-файлами.
- **Markdown-редактор для постов**: ✅ закрыто в 1.11.0 — используется WYSIWYG
  `@mdxeditor/editor`; на выходе Markdown, HTML рендерит/санитизирует сервер (ленивый чанк).
- **Размер файлов вложений постов** не показываем: в таблице `files` нет колонки
  размера (в схеме есть только у `additional_materials`/`consent_files`). Если UI
  потребует размер — добавим позже (правка схемы) либо посчитаем на лету.
- **`files`/`file_categories`**: общий реестр файлов пока используется для вложений
  постов и PDF-выгрузок; «полноценный» модуль с категориями не развиваем до появления
  реальной потребности.

## Отложенные решения

- **Антивирус**: ClamAV не внедряем (слабый сервер; строгий allowlist + проверка
  содержимого + UUID + запрет исполнения). При желании позже — on-demand `clamscan`.
- **Автотесты**: запланированы (unit + интеграционные, Newman) — см. `AGENTS.md`/`PLANS.md`.
- **Очистка старых файлов** — `bun storage:cleanup`, повесить в cron на проде.
- **Пагинация `/api/reviews`** — сейчас список без ограничения; добавить при росте данных.
