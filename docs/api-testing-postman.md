# Проверка API в Postman (Сессия 1)

Готовая коллекция: `postman/arbuz-crm.postman_collection.json`.
Проверять можно вообще без опыта — нужно только пройти по шагам.

## 1. Подготовка

1. Убедиться, что БД доступна, а в `.env` заполнены `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
2. Из корня проекта выполнить:
   ```sh
   bun db:generate
   bun db:push
   SEED_DEMO=true bun seed   # создаст админа и демо-заявку/участника
   bun dev
   ```
   Демо-учётка по умолчанию: `demo@arbuz.local` / `demo12345`, но для админ-запросов
   используются `ADMIN_EMAIL`/`ADMIN_PASSWORD` из `.env`.
3. Проверить, что backend ответил «запущен» на `http://127.0.0.1:3000`.

## 2. Импорт коллекции

Postman → кнопка **Import** → перетащить файл `postman/arbuz-crm.postman_collection.json`.

## 3. Переменные

В коллекции уже заданы переменные (значения можно поменять в `...` → Edit → Variables):

| Переменная       | Значение по умолчанию  | Что это                          |
| ---------------- | ---------------------- | -------------------------------- |
| `baseUrl`        | `http://127.0.0.1:3000`| адрес backend                    |
| `adminEmail`     | `admin@arbuz.local`    | email админа (см. `.env`)        |
| `adminPassword`  | `admin12345`           | пароль админа (см. `.env`)       |
| `applicationId`  | `1`                    | id демо-заявки из seed           |
| `teamMemberId`   | `1`                    | id демо-участника из seed        |
| `fileId`         | `1`                    | id файла (подставить из ответа «Список материалов») |

## 4. Порядок запуска

1. **«1. Вход»** — после успешного входа Postman автоматически сохранит httpOnly-cookie
   `arbuz_session` и будет подставлять её в остальные запросы.
2. **«3. Загрузить материал»** — на вкладке Body в строке `file` нажмите *Select Files*
   и выберите файл: PDF, DOCX, JPEG, PNG или MP4 (до 10 МБ).
3. **«4. Список материалов»** — в ответе появятся объекты с `id`; если это первый файл,
   `id` будет `1` и `fileId` менять не нужно.
4. **«5. Скачать» / «6. Удалить»** — проверка скачивания и удаления.
5. **«7. Загрузить согласие» / «8. Список согласий»** — то же для файла согласия участника.

## 5. Если что-то не так

- **401 «Требуется авторизация»** — cookie не сохранилась; выполните «1. Вход» ещё раз.
- **404 «Заявка не найдена»** — `applicationId` не совпадает (демо-заявка создаётся только при `SEED_DEMO=true`).
- **413** — превышен лимит (10 МБ/файл, 25 МБ/заявка) — уменьшите файл.
- **415** — недопустимый тип или содержимое не совпадает с расширением.
- **504/нет ответа** — backend не запущен или не тот порт.
