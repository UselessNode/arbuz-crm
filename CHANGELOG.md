# Changelog

Все заметные изменения проекта фиксируются в этом файле.

**Правило версионирования:** каждое изменение (фикс, фича, рефакторинг) поднимает версию пакетов воркспейсов — `apps/backend`, `apps/frontend`, `packages/shared` (все синхронно, семантическое версионирование). Версия фиксируется в git-коммитах и вносится в этот файл.

## [1.13.0] - 2026-09-11

MVP-3 (часть A): экспертный контур + правка редактирования заявок.

### Fixed

- Владелец заявки (в т.ч. пользователь, которому заявку создал администратор) может редактировать
  свою заявку; отправка больше не переводит её в «только чтение» (гейт по `status.is_editable`
  и `submitted_at` для владельца убран).

### Added

- **Область эксперта** `/expert`: список назначенных заявок; карточка заявки в режиме чтения
  (`area="expert"`), включая материалы и согласия.
- **Форма оценки эксперта**: критерии конкурса (значения в диапазоне `min..max` с весами),
  вердикт и текст рецензии; `total_score` считает сервер, сумма с весами показана на клиенте.

### Changed

- Критерии конкурса: **чтение** доступно авторизованным (экспертам), изменения — администратору.
- Навигация и вход: эксперт → `/expert`.

## [1.12.0] - 2026-09-11

MVP-2: функционал заявителя.

### Added

- **Область заявителя**: `/applications` — список «Мои заявки» с пагинацией и создание заявки.
- **Карточка заявки** общая для администратора и заявителя: после отправки владельцу — только чтение
  (состав, план, бюджет, материалы, согласия).
- Заявитель видит статус и рецензии экспертов (без управления); свой вердикт и балл.
- Администратор: создание заявки с **обязательным выбором владельца** (заявителя).
- Общий `ApplicationFormModal` (создание/редактирование) и хелпер `homePathForRole`.

### Changed

- Справочники (конкурсы/направления/статусы): **чтение** доступно любому авторизованному, изменения — admin.
- Материалы/согласия заявки: изменение только в редактируемом статусе (после отправки владелец не может менять).
- Навигация и вход: заявитель → «Мои заявки» (`/applications`), эксперт → профиль (MVP-3).

## [1.11.0] - 2026-09-11

Доработки MVP-1: редактор публикаций, уведомления, вёрстка.

### Added

- **WYSIWYG-редактор публикаций** (`@mdxeditor/editor`) вместо markdown-textarea: панель
  форматирования для неподготовленного пользователя. На выходе — по-прежнему Markdown,
  HTML формирует и санитизирует сервер (`contentHtml`); редактор грузится отдельным ленивым чанком.
- **Toast-уведомления** (`ToastProvider`/`useToast`): тона `success`/`error`/`info`, авто-скрытие
  с паузой при наведении и кнопка **«Отменить»** для обратимых действий.
- Уведомления подключены к действиям: смена роли пользователя, публикация поста, смена статуса
  заявки (с отменой), а также сохранение/удаление пользователей, постов, участников, файлов и
  элементов справочников.

### Changed

- Домашняя страница переверстана: чёткая иерархия (hero → секция публикаций → боковые контакты),
  типографика Markdown-содержимого.
- Вход/регистрация на публичной странице перенесены вправо.

### Removed

- Серверный предпросмотр Markdown `POST /api/posts/preview` и `postsApi.preview` — не нужны
  с WYSIWYG; HTML для показа по-прежнему формируется на сервере в `contentHtml`.

## [1.10.0] - 2026-09-11

MVP-1: публичный каркас, согласия, регистрация-соглашение.

### Added

- **Публичная домашняя страница** `/` с лентой опубликованных публикаций (с пагинацией)
  и блоком контактов организации; страницы `/about` и `/privacy`.
- **Каркасы**: публичный `PublicLayout` и авторизованный `AppLayout` с навигацией по ролям;
  **цвет шапки зависит от роли** (админ — серый, эксперт — зелёный, заявитель/гость — синий);
  общий футер (ссылки, контакты, копирайт).
- **Согласия участников**: загрузка/просмотр/скачивание/удаление в карточке заявки (`ConsentModal`),
  раздел `consents` в API-клиенте, у участников — `hasConsent`/`consentsCount`.
- **Проверка готовности заявки** к отправке: ≥1 участник, совершеннолетний координатор,
  согласие у каждого участника (`GET /api/applications/:id/validation`); отправка блокируется.
- **Регистрация**: обязательное соглашение (модалка с текстом политики), индикатор прокрутки,
  кнопка «Согласиться и продолжить»; в dev — удержание чекбокса (1.5 с).
- **Карточка заявки**: кнопка «Отправить на проверку» с диалогом удаления участников
  без согласия и повторной проверкой состава.

### Changed

- `GET /api/posts` и `GET /api/posts/:id` доступны без авторизации (гость видит только
  опубликованные); добавлена пагинация `limit/offset`, ответ `{ posts, total }`.
- `submitApplication` проверяет валидность состава (400 `APPLICATION_INVALID`).

### Removed

- `AdminLayout` заменён на `AppLayout`; `HomeRedirect` заменён публичной домашней страницей.

## [1.9.0] - 2026-09-11

Аудит кода и исправление найденных проблем (костыли, заглушки, технический долг).

### Fixed

- **Хранилище файлов**: пути в БД (namespace `uploads/`) и физический каталог (`UPLOAD_DIR`)
  приведены к единой конвенции; устранена двойная вложенность `uploads/uploads/`. `storage:cleanup`
  больше не удаляет «живые» файлы — пути сопоставляются корректно.
- **Отправка/создание заявки**: убран хардкод имени и id статуса («На проверке», `status_id: 1`);
  системные статусы вынесены в константы (`lib/app-status.ts`), нужный статус ищется по имени
  с понятной ошибкой.
- **Заявки**: при создании/обновлении проверяется существование конкурса/направления и их
  согласованность; `status_id` (admin) валидируется и не может стать `null` — вместо ошибки
  Prisma возвращается 400.
- **PDF-экспорт**: у фонового воркера появились watchdog и обработка аварийного завершения —
  задание не «зависает» в `pending`/`processing`.
- **Доступ к файлам**: назначенный эксперт получает доступ на чтение/скачивание материалов и
  согласий заявки (управление остаётся за владельцем/админом).
- **Frontend**: удалён недостоверный справочник `APPLICATION_STATUS_OPTIONS`; статусы заявок
  в списке и карточке берутся из `GET /api/application-statuses` (единый источник).
- **Frontend**: показываются ошибки загрузки конкурсов/направлений в форме заявки и ошибки
  предпросмотра Markdown; вложения постов получили состояние загрузки; `AccountPage` вместо
  пустого экрана показывает сообщение.
- **Frontend**: убран stale-closure под `eslint-disable` в списке пользователей; скачивание
  материала — без вложенного `<a><button>`; кнопка в состоянии загрузки показывает спиннер;
  `Modal` получил фокус-трап и `aria-labelledby`; кликабельные строки таблицы доступны с клавиатуры.

### Changed

- `API_VERSION` берётся из `package.json` (единый источник); соединение Prisma использует
  `config.databaseUrl`; `uploads/` и `logs/` привязаны к корню пакета backend, а не к рабочему каталогу.
- Cookie-сессия использует `config.jwt.cookieMaxAgeMs`; роль из JWT валидируется по `RoleType`.
- `GET /api/applications` (список): поле `status` теперь объект `{ id, name } | null` (как в детали).

## [1.0.3] - 2026-09-08

Сессия 1 — базовая работа с файлами.

### Added

- **Аутентификация**: вход по email + паролю (argon2id), JWT в httpOnly-cookie (`arbuz_session`); `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`. Архитектура допускает добавление внешних провайдеров (Госуслуги/ВК) в будущем.
- **Хранение файлов**: локальный диск `./uploads/` (самодостаточное хранилище без облаков); на каждую заявку каталог `<owner_id>-<application_id>-<время>`, согласия — в подкаталоге `consents/`; в БД хранятся относительные пути `uploads/...`.
- **Файлы заявки**: `POST/GET /api/applications/:id/files`, скачивание и удаление материалов (`additional_materials`); согласия участников команды (`consent_files`) со своим набором маршрутов.
- **Проверки**: разрешены PDF, DOCX, JPEG, PNG, MP4 — проверка по содержимому (магические байты) и расширению; переименование в UUID; лимиты 10 МБ на файл и 25 МБ на заявку.
- **Права**: доступ к файлам заявки — у владельца и администратора; остальные маршруты требуют аутентификации.
- **Скрипты**: `bun seed` (администратор и опциональные демо-данные), `bun storage:cleanup` (очистка удалённых и осиротевших файлов — для cron).
- **Аудит**: журнал `logs/audit.log` (вход, загрузка/скачивание/удаление файлов).

### Added

- Монорепозиторий на Bun workspaces: `apps/backend`, `apps/frontend`, `packages/shared`.
- Backend: Express-сервер с маршрутами `GET /` и `GET /health` (проверка подключения к БД), graceful shutdown.
- Подключение к PostgreSQL через Prisma 7 + driver adapter `@prisma/adapter-pg`.
- Prisma Client генерируется в `packages/shared/src/generated/prisma` и раздаётся воркспейсам через `@arbuz/shared`.
- Frontend: React 18 + Vite, прокси запросов `/api` и `/health` на backend.
- Скрипты корня: `dev`, `dev:backend`, `dev:frontend`, `typecheck`, `run build`, `db:*`.
- Загрузка `.env` для backend через `dotenv-cli`.
- `README.md`, `.gitignore`, `.env.example`.
